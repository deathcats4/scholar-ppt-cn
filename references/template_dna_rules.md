# Template DNA Rules

When a visual template or reference is used for a new deck or broad redesign, extract Template DNA as the visual-consistency layer before production planning. This applies both to similar-style recreation and to editable source-PPTX continuation. Skip Template DNA only when the task is content-only planning or a localized/mechanical revision that does not require visual redesign.

Extract visual identity from the reference/template deck:

- canvas and background behavior;
- institutional or brand identity;
- title hierarchy and title treatment;
- footer and page-number styling;
- exact or observed palette;
- typography roles and weights;
- caption and source-note styling;
- recurring lines, bars, blocks, borders, dividers, ribbons, cards, and emphasis language;
- reusable micro-components and decorative motifs;
- local spacing and alignment rhythm that belongs to the visual system.

Template DNA describes how the deck should look. It does not decide the scientific narrative or the body layout of a slide.

Do not infer full-slide composition from Template DNA. Do not treat the reference deck's old result pages, discussion pages, data pages, microscopy pages, full-page layouts, placeholder geometry, slide-layout inventory, old table of contents, or old research structure as layout candidates unless the user explicitly asks to preserve or reuse a named page layout.

For editable source-PPTX continuation, use Template DNA together with direct native-asset reuse:

- Template DNA keeps newly designed slides visually consistent with the source deck.
- Native Theme/Master/backgrounds and recurring editable objects should be reused directly when available.
- When a recognizable native asset can be reused, prefer the native asset over an approximate redraw.
- Template DNA remains useful even when native assets are reused because new slide compositions may require visual elements that do not exist as ready-made source objects.

For screenshot, PDF, image, or similar non-editable references, Template DNA becomes the main way to recreate the visual system.

Preserve exact native page structure and object positions only when the user explicitly requests strict/in-place layout preservation or identifies a source page whose layout should be reused.
